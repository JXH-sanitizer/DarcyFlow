## 1. 背景介绍
### 1.1 业务背景

DarcyFlow，顾名思义，达西流。达西定律是所有地下水运动的起点，每一个水文地质学生入门的第一课就是达西定律。在地下水环境建模中，MODFLOW 系列是绕不开的话题，而 FloPy，就是基于 MODFLOW 并抽象出的一个 Python 工具包，将 MODFLOW API 外化为一系列 Python API，由开发者撰写，并在内部调用 MODFLOW 能力进行建模，可以说是连接水文领域的开发者和专业水文模型的桥梁。然而，FloPy 本身基于 MODFLOW 开发，因而其中的水文地质知识艰深晦涩，同时 FloPy API 复杂多样，每一个 API 参数多且复杂，维护的官方文档又是英文版本，不利于国内的开发者和学习者进行学习和上手。因此本项目针对上述痛点，开发出一套 "地下水 + 教学 + 轻量建模"的 Web First 应用，帮助每一位坐在电脑前写课程作业/毕设的水文地质同学，快速上手 FloPy，并能一眼看出模型是怎么跑的，代码是怎么写的，结果是怎么样的。

笔者本身是环境规划与管理领域出身的全栈工程师，也在无数个深夜为 FloPy 和 MODFLOW 辗转反侧，因此尽管本项目属于个人 Vibe Coding 项目，但也依然希望站在无数个水文地质同学视角，不断优化不断提升项目覆盖范围，从单层饱和含水层二维稳定流到多层含水层三维瞬态流等，持续迭代。

## 2. 产品概述

### 2.1 一句话定位
DarcyFlow 是一个 **FloPy 教学器**：用户在画布上点选完成地下水建模，实时看到模型被"翻译"成的 FloPy 代码，一键运行并查看结果——建模工具同时是 FloPy 学习器。

### 2.2 产品边界（不做什么）
- **不是网页版 Visual MODFLOW**：不追求覆盖完整建模能力
- 不面向生产项目：不做真实地图选点、坐标系、GIS 数据接入
- V1 无账号体系、无云端保存、无社区功能

### 2.3 目标用户
- **主画像**：地下水科学与工程 / 水文地质方向的本科生、研究生
- **主场景**：课程作业、毕设入门——需要用 MODFLOW/FloPy 建一个概念模型写进报告，但啃不动英文 API 文档
- **使用环境**：坐在电脑前使用（桌面 Web）

### 2.4 核心用户流程
1. 打开页面 → 看到建模画布 + 参数面板 + 代码预览区
2. 设置网格：行数、列数、单元尺寸 → 画布生成结构网格
3. 选岩性模板（如"中砂"）→ 渗透系数自动填入经验值，可手动改；术语可点击查看解释
4. 在网格上点击放置边界条件：定水头边界、抽水井
5. 代码预览区随每一步操作**实时更新**
6. 点击运行 → 后端建模并调用 MODFLOW → 前端渲染水头等值线
7. 导出 FloPy 脚本（.py）和/或模型参数（.json）
8. （失败路径）模型不收敛/报错 → 展示 MODFLOW 输出摘要 + 中文原因提示，而非转圈或白屏

### 2.5 成功标准
V1 的验收标准：零 FloPy 基础的目标用户，10 分钟内完成"建网格 → 设参数 → 放井 → 跑出等值线 → 导出脚本"全流程，并且能说出脚本里每一段代码对应他在界面上的哪一步操作。

### 2.6 竞品与替代方案
| 替代方案 | 不足 | DarcyFlow 的差异 |
| --- | --- | --- |
| 直接啃 FloPy 官方文档 | 英文、API 繁多、无即时反馈 | 所见即所得 + 代码即时映射 |
| Visual MODFLOW | 商业闭源、重、不产生代码能力 | 轻量 Web、输出 FloPy 学习路径 |
| 课程教材 / PPT 例题 | 静态、不可交互 | 参数可改、结果立现 |

## 3. 需求说明

### 3.1 需求列表
> P0 = V1 必须交付；P1 = V1 争取（或顺延 V1.1）；P2 = 后续大版本；— = 明确不做/远期。

| 需求 | 模块 | 目标 | 优先级 |
| --- | --- | --- | --- |
| FloPy Playground：网格设置、参数配置、边界放置、运行与水头渲染 | 核心功能 | 单层二维稳定流的最小可用建模闭环 | P0 |
| FloPy 脚本实时预览与导出 | 核心功能 | 参数变化实时生成脚本，随时可导出 .py，无需先运行 | P0 |
| 术语知识库（tooltip 解释，前端硬编码） | 教学辅助 | 水文术语中文解释 + 岩性经验取值 | P1 |
| 模型参数导入导出（JSON 文件） | 效率 | 替代"保存/加载"，顺带覆盖分享场景 | P1 |
| 账号体系 / 云端保存 | — | 后置 V4（游客 UUID 方案已否决，见决策表 #4） | P2 |
| 广场交流 | — | 远期不做 | — |

### 3.2 需求明细

#### 3.2.1 FloPy Playground（P0）
**V1 模型假设**：单层含水层、均质、各向同性、**二维稳定流**、规则结构网格（MODFLOW DIS 包）。

- 单位制：全站固定长度 meter、时间 day。派生单位随之固定——渗透系数 m/d、抽水井流量 m³/d、水头 m；所有参数输入框显式标注单位，不提供单位切换
- 网格设置：行数、列数、单元尺寸（上限 100×100）
- 水文参数：渗透系数 K，提供岩性模板（黏土/细砂/中砂/粗砂/砂砾…），自动填入经验范围默认值并附解释文案
- 边界条件最小集：**定水头边界 CHD**（指定水头值）、**抽水井 WEL**（指定流量，可放置多口）
- 运行链路：参数 JSON → FastAPI → FloPy 建模 → 调用 MODFLOW 6（mf6）→ FloPy 的 HeadFile reader 读取结果（无需第三方格式转换工具）→ 水头数组以 JSON 返回
- 结果渲染：二维水头等值线 / 热力图（Canvas/ECharts 量级即可）
- 失败路径：不收敛或运行报错时，前端展示 MODFLOW 输出摘要 + 中文原因提示——学生踩坑时刻恰是教学时刻

#### 3.2.2 FloPy 脚本实时预览与导出（P0）
- 参数面板的每次修改**实时更新**脚本预览（输入 → 代码的即时映射是本产品的教学核心）
- 脚本带中文注释，标注每段代码对应的界面操作
- 导出 .py 源文件；降级方案：.txt
- 导出不要求先运行过模型

#### 3.2.3 术语知识库（P1）
- 词条前端硬编码 JSON（V1 预计 ≤ 20 条：水头、渗透系数、定水头边界、稳定流、抽水降深、水力梯度、单位自洽…）
- 交互：术语高亮，点击/悬停弹出解释卡片
- 词条规模起来之前不建后端术语库（见决策表 #10）

#### 3.2.4 模型参数导入导出（P1）
- 导出：全部模型参数序列化为 .json 文件（含 schema 版本号）
- 导入：读取 .json 还原画布状态，可继续修改、再次运行
- 该功能替代原"模型保存和加载"需求，并顺带覆盖大部分"分享模型"场景（文件发给同学即可）

#### 3.2.5 账号体系与广场（不做 / 后置）
- V1–V3 无账号体系。核心流程是无状态计算，不需要身份；云端保存与账号一并后置 V4
- 广场交流：远期不做

### 3.3 非功能需求
- **性能**：网格 ≤ 100×100 时，单次运行端到端 < 30s；超时返回可读错误
- **计算模式**：V1 同步 HTTP 请求（异步任务队列属过度设计，见决策表 #11）
- **系统依赖**：开发机与服务器均需安装 MODFLOW 6 可执行文件（`mf6`）并加入 PATH；FloPy 只负责生成输入与读取输出，本身不含求解器
- **浏览器兼容**：桌面端最新版 Chrome / Edge / Safari；移动端浏览器可访问但不保证体验
- **平台**：仅桌面 Web；小程序明确不做（触屏交互不成立 + 域名备案门槛 + Canvas 能力受限）；桌面客户端（Electron）列为远期可能项
- **安全**：服务端校验参数合法性（K > 0、井位必须在网格内、行列数不超上限），防异常输入撑爆计算

## 4. 关键决策表
> 决策 / 理由 / 被否方案。新增决策按此格式追加。

| # | 决策 | 理由 | 被否方案 |
| --- | --- | --- | --- |
| 1 | 后端 Go → Python（FastAPI） | FloPy 是 Python 库，用 Go 需起子进程包一层，无意义 | Go + 子进程调 Python |
| 2 | 前端 React → Vue 3 | 框架不是本项目的风险点，模型链路才是；顺带拓宽技术栈 | React（日常工作已在用） |
| 3 | 数据库 MySQL | V1 仅岩性模板等少量数据；V4 账号/保存仍用得上 | — |
| 4 | V1 无身份体系 | 核心流程是无状态计算；保存需求用 JSON 导入导出覆盖 | 注册登录；游客 UUID + LocalStorage（清缓存即丢保存数据，伤害大于价值） |
| 5 | 脚本导出升 P0，且实时预览、无需先运行 | "工具即学习器"的定位兑现点；脚本只依赖参数不依赖结果 | 仅运行后可导出（v0.1 原方案） |
| 6 | V1 仅规则结构网格（DIS） | 教学场景的最小充分集 | 不规则网格 DISV（后置） |
| 7 | 边界条件最小集 CHD + WEL | 覆盖"两侧定水头 + 抽水井"经典教学场景 | RCH 补给等（后置 V2） |
| 8 | 地图（Mapbox）后置 | 教学模型多为假想概念模型，无需真实地理坐标；Mapbox 国内访问不稳定且需 token | V1 接入真实地图选点 |
| 9 | Three.js 后置 V2 | V1 二维等值线用 Canvas/ECharts 足够 | V1 引入 3D 渲染 |
| 10 | 知识库前端硬编码 | 词条 ≤ 20，建库 + 接口是杀鸡用牛刀 | 后端术语数据库 + API |
| 11 | 运行采用同步 HTTP | V1 网格小、计算快 | Celery/RQ 异步队列（过度设计） |
| 12 | V1 固定单位制：长度 meter、时间 day | MODFLOW 不做单位换算、只要求单位自洽；混用单位（如 m/s 与 m/d）是新手高频翻车点，锁死单位直接消灭这类错误 | 提供多单位切换（UI 与校验复杂度上升，教学收益低） |

## 5. 分期规划
- **V1**：单层二维稳定流 Playground + 脚本实时预览/导出（P1 项争取同版交付）
- **V2**：非稳定流、多层含水层、Three.js 3D 展示、更多边界条件（RCH…）
- **V3**：溶质运移（MT3D）+ 浓度羽流动画
- **V4**：账号体系、云端保存、模型分享

## 6. 风险与开放问题
- 不收敛提示的中文解释质量：需要积累一批"典型报错 → 人话解释"的映射，开发期逐步沉淀
- 等值线渲染方案未定：ECharts 热力 / 自绘 Canvas / d3-contour，开发期选型并补记决策表
- 脚本实时预览的实现位置：前端模板拼接 or 后端渲染返回，开发期定
- 正确性验证方法：用 FloPy 官方示例模型对拍（同参数比水头结果）
- 网格上限与运行时长的实测关系，待 M1 完成后校准
