## 核心概念：MODFLOW 的"包"思想

一个 MODFLOW 模型 = 一组文本文件，每个文件对应一个"包"（Package），各管一类事情。FloPy 做的事就是用 Python 对象帮你生成这堆文件：

| 包 | 职责 | 对应参数里的什么 |
|---|---|---|
| TDIS | 时间离散（几个应力期） | 写死：1 期稳定流 |
| IMS | 迭代求解器设置 | 用默认 |
| GWF | 地下水流模型本体 | modelname |
| DIS | 空间网格：行列数、单元尺寸 | nrow/ncol/delr/delc |
| NPF | 渗透系数 | k |
| IC | 初始水头（迭代起点） | 写死 1.0 |
| CHD | 定水头边界 | chds |
| WEL | 抽水/注水井 | wells |
| OC | 输出控制（水头存到哪个文件） | 写死 .hds |

## 学到的知识点

### FloPy 的"注册式"写法

`tdis = flopy.mf6.ModflowTdis(sim, ...)` 这种赋值后变量再没被用过，IDE 会标灰提示"未使用"——**不是废代码**：包在构造时通过第一个参数（sim 或 gwf）自动挂到父对象上，变量名只是留个句柄，删掉包就丢了：

```python
sim = flopy.mf6.MFSimulation(sim_name="demo", sim_ws=ws, exe_name="mf6")
tdis = flopy.mf6.ModflowTdis(sim, nper=1, perioddata=[(1.0, 1, 1.0)])
# tdis 变量没再用？正常的，它已经挂到 sim 上了
```

### 边界条件的数据形状（最容易踩的坑）

CHD/WEL 包的 `stress_period_data` 是列表，每个元素是 **"坐标元组 + 值"组成的二元组**——双层括号，少一层就崩：

```python
# 错：append 收到了两个参数，TypeError
chd_spd.append((0, row, col), head)
# 对：((layer, row, col), head) 整体作为一个元素
chd_spd.append(((0, row, col), head))
# 更 Pythonic 的写法：列表推导式
chd_spd = [((0, c.row, c.col), c.head) for c in params.chds]
```

### 运行结果别假设成功

`run_simulation()` 返回 `(是否成功, 日志列表)`，失败时把日志末尾带进异常，方便定位原因：

```python
success, buff = sim.run_simulation(silent=True)
if not success:
    # buff 是字符串列表，join 拼接后取末尾 800 字符（错误原因几乎总在结尾）
    raise RuntimeError(f"MODFLOW 运行失败:\n{''.join(buff)[-800:]}")
```

### 读水头：二进制文件 → JSON 友好的列表

水头结果存在 OC 包指定的 `.hds` 二进制文件里，用 `flopy.utils.HeadFile` 读，注意 shape 是 (层数, 行, 列)，且 numpy 数组不能直接被 FastAPI 序列化：

```python
head_file = flopy.utils.HeadFile(sim_ws + f"/{params.modelname}.hds")
result = head_file.get_data()[0].tolist()   # [0] 取第 0 层，tolist() 转普通列表
```

### Python 最大的坑：模块查找路径（对比 Node.js）

`python scripts/test_run.py` 找不到 `app` 包——因为 Python 只把**脚本所在目录**（scripts/）加进模块搜索路径，不是终端所在目录。Node.js 会从当前目录往上逐级找 node_modules，Python 没有这个机制。

```bash
# 错：No module named 'app'
python scripts/test_run.py
# 对：显式把当前目录加进搜索路径（在 Backend/ 下执行）
PYTHONPATH=. python scripts/test_run.py
# 也对：-m 方式从项目根跑
python -m scripts.test_run
```

一劳永逸的方案是配 `pyproject.toml` 后 `pip install -e .`，以后再做。

### 用户输入要当文件名用时的安全约束

`sim_name` 会变成磁盘上的文件名（sim_name.nam 等），光限制长度挡不住 `../` 这种输入，要限制字符集：

```python
sim_name: str = Field(min_length=3, max_length=50, pattern=r"^[a-zA-Z0-9_-]+$")
```

## 补充：今天还做完了 M2 接线 + 回归测试

### 超时要自己实现（FloPy 不提供）
`run_simulation()` 的参数里根本没有 timeout，而 mf6 是独立的外部进程。用 `subprocess.run` 自己拉进进程才能真的杀掉它：

```python
RUN_TIMEOUT = 30
run_result = subprocess.run(
    ["mf6"],                 # 列表形式不走 shell，天然免疫命令注入
    cwd=sim_ws,              # 必须！mf6 只认当前目录下的 mfsim.nam
    capture_output=True,    # 把子进程输出抓回来
    text=True,              # 给字符串而不是字节串
    timeout=RUN_TIMEOUT,    # 超时杀进程并抛 TimeoutExpired
)
```

### 自定义异常类：让 API 层能按类型分流
services 层抛自己的异常类型，不知道 HTTP 的存在；API 层按类型映射状态码（400/504）。这样 `build_and_run_model` 能脱离 Web 单测，将来接 CLI / 队列也能复用：

```python
class ModelRunError(Exception):
    def __init__(self, log_tail: str):
        self.log_tail = log_tail            # 数据挂在异常对象上，给下游取用
        super().__init__(f"MODFLOW 运行失败:\n{log_tail}")
```

```python
# endpoints/model.py
 except ModelRunError as e:
    raise HTTPException(status_code=400, detail={
        "code": "MODEL_RUN_ERROR",         # 给前端做分支
        "message": "模型未收敛或求解失败……",  # 给用户看
        "log_tail": e.log_tail,            # 给老师/进阶用户看
    })
```

### 判断成败：退出码不可靠，要靠结束语（已实测）
mf6 **不收敛时退出码依然是 0**，所以光查 `returncode` 会漏。真正的判据是输出里那句结束语：

- 算完：`Normal termination of simulation.`
- 不收敛：`Premature termination of simulation.` + `ERROR REPORT: Simulation convergence failure ...`

```python
# 坑：mf6 打的是 "Normal"（首字母大写），比较前必须转小写
 if run_result.returncode != 0 or "normal termination" not in run_result.stdout.lower():
    raise ModelRunError(log_tail=run_result.stdout[-800:])
```

错误信息总在日志末尾，所以 `[-800:]` 取尾部是对的。

### 临时目录清理：try/finally
```python
finally:
    shutil.rmtree(sim_ws, ignore_errors=True)   # 清理失败不能把主流程带崩
```

两个铁律：`finally` 里不要 `return`（会静默吞掉异常）；`except` 不能脱离 `try` 单独存在。

### 接口函数必须是 `def` 而不是 `async def`
`build_and_run_model` 是阻塞的（等子进程最多 30 秒）。标成 `async def` 会卡住整个事件循环，期间所有用户请求全部堆积；写成普通 `def`，FastAPI 会自动丢进线程池，并发安全。这是同步/异步混用最容易犯的错。

### 回归测试：TestClient + mock
`scripts/test_api.py` 跑 16 项断言，全部 PASS。两个关键技巧：

1. **mock 返回值才是真正的替身**：`mock.patch(..., return_value=fake)`，不是 `mock.patch(..., fake)`——后者返回的是空的 Mock 对象，一切片就 `TypeError`

```python
fake_completed = mock.Mock(returncode=0, stdout="x" * 900 + "\n...Premature termination of simulation.\n")
with mock.patch("app.services.model_builder.subprocess.run", return_value=fake_completed):
    resp = client.post("/api/v1/model/run", json=OK_BODY)
```

2. **mock 要模仿真实行为的形状**：第一版把错误行放在伪造日志的开头，马上被 `[-800:]` 截掉了——测试自己写错反而测出了真实的设计问题（截断策略）
