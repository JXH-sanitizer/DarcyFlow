## 学到的知识点

### 虚拟环境（venv）
给项目单独圈一块地装依赖包，不影响系统里的 Python。终端里激活它，和编辑器里选择它，是两回事——编辑器没代码提示时，去命令面板选 "Python: Select Interpreter"，指向 `.venv/bin/python`。

```bash
python3 -m venv .venv          # 创建虚拟环境
source .venv/bin/activate      # 终端激活（命令行前出现 (.venv)）
```

### Pydantic 校验数据
- 类继承 `BaseModel`，字段写上类型（`int`、`float`），传入数据类型不对就会自动报错：

```python
from pydantic import BaseModel, Field

class Well(BaseModel):
    row: int = Field(ge=0)      # ge = 大于等于
    col: int = Field(ge=0)
    rate: float                 # 不加限制：抽水(负)注水(正)都可以
```

- `Field(gt=0, le=100)` 这种写法可以加范围限制，替代手写 if 判断
- 字段不给默认值 = 必填；`default_factory=list` 表示默认空列表
- 需要跨字段比较时（比如"井的位置不能超出网格"），用 `@model_validator(mode="after")`，等所有字段都填完再检查：

```python
from pydantic import model_validator

@model_validator(mode="after")
def check_row_and_col(self):
    for well in self.wells:
        if well.row >= self.nrow or well.col >= self.ncol:
            raise ValueError("Well position out of bounds")
    return self
```

- 一个字段想支持两种形态（比如渗透系数既可以是单个数字也可以是二维数组），用联合类型，还能用 `Annotated` 把限制贴到每种形态上：

```python
from typing import Annotated

k: Annotated[float, Field(gt=0)] | list[list[Annotated[float, Field(gt=0)]]]
#  传 10.0 就是均质含水层；传二维列表就是每个格子各自的渗透系数
```

### 踩过的两个坑
1. **默认值不会被校验**：写了 `min_length=1` 同时又给 `default_factory=list`，不传这个字段时会拿到空列表，限制根本没生效。必填的字段就别给默认值

```python
chds: list[CHDHead] = Field(default_factory=list, min_length=1)  # 错：空列表绕过校验
chds: list[CHDHead] = Field(min_length=1)                        # 对：必填且至少 1 个
```

2. **数组只查第一行**：检查二维数组形状时只判断了 `k[0]`，后面行缺斤短两就漏过去了。要用循环把每一行都查一遍

```python
if len(self.k[0]) != self.ncol:            # 错：只查了第 0 行
    ...
for i, row in enumerate(self.k):           # 对：逐行检查，报错还能带行号
    if len(row) != self.ncol:
        raise ValueError(f"k column count mismatch in row {i}: ...")
```

### 422 错误的结构（前端设计要用）
把 `ModelParams` 标为接口参数类型，校验逻辑就自动生效了：

```python
# app/api/v1/endpoints/model.py
@router.post("/model/run")
def run_model(params: ModelParams):   # 类型标注即校验，非法请求自动 422
    return params

# app/main.py
app.include_router(model_router, prefix="/api/v1")   # 最终路径 /api/v1/model/run
```

参数不合法时，接口返回的错误列表里每条带：

```json
{
  "detail": [
    {
      "type": "greater_than_equal",
      "loc": ["body", "nrow"],
      "msg": "Input should be greater than or equal to 1",
      "input": -5
    }
  ]
}
```

- `loc`：错误在哪个字段，比如 `["body", "nrow"]`，前端靠它定位到具体输入框
- `msg`：错误原因文案，我们自己写的校验错误只会标 `["body"]`，所以文案里必须写清"期望几行、实际几行"
- 字段级错误会一次性全部返回；自定义校验器里的错误一次只报一个（遇到第一个就停了）
